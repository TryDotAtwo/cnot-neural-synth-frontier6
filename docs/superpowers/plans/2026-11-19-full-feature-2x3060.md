# Full-feature training on 2x RTX 3060

## Objective

Measure and work toward 100 epochs of 10,000 training records in about 48 hours on two RTX 3060 GPUs. Keep the original eight-block model, its 136,421,807 parameters, and the complete 102-input feature contract. Do not claim the time target without a real end-to-end run on the declared two-GPU setup.

## Constraints

- Rebuild the missing 10,000-record train panel from deterministic, replayable synthetic CNOT reductions. Preserve the public 1,792-record dev and 1,792-record test panels from the Hugging Face holdout release.
- Give the rebuilt artifact a new SHA-256. Validate certificates, split identities, finite-symmetry separation, and one-hop separation before training.
- Keep datasets, checkpoints, measurements, and quality outputs on the remote Vast disk. Keep Windows source-only. Route instance control and remote execution through GitHub Actions and keep its public output redacted.
- Cap all project Vast charges at the user-authorized $20. Stop paid resources after the bounded run.
- Use one logical sampler and one AdamW update per logical batch. Split each batch over two full model replicas, average gradients before the update, and synchronize weights before the next batch.

## Work sequence

1. Add a deterministic remote dataset builder that converts the pinned holdout SQLite records and creates exactly 10,000 new train records across all 14 widths. Use walk, structured-shear, and composition families with verified reduction words; leave exact distances unset unless proved.
2. Validate the generated artifact and its new digest using the project's frozen-data loader. Do not copy the generated artifact to Windows or GitHub.
3. Extend the CUDA training path for two replicas while preserving feature coverage, checkpoint identity, sampler semantics, per-example loss averaging, finite-gradient checks, and rollback behavior.
4. Add a GitHub Actions controller that runs only the selected bounded workflow, provisions/reuses a verified two-GPU 3060 target within the existing budget gate, keeps raw outputs on the remote disk, and verifies stop/key-cleanup state.
5. For the first speed run, set sampled_neighbor_count=4 and compare deterministic dev/test quality before and after a bounded training segment. The current sampler keeps the two lowest parent-Qhat actions and adds two deterministic exploration actions; it computes full features for those children while retaining the full eight-block network and all 102 inputs. On the rebuilt 10k width cycle this reduces child-candidate evaluations from 50,296,490 to 40,000 per epoch (about 1,257x by candidate count; not a measured speedup). Parent features and Qhat scores for every primitive action remain. Retain exact run fingerprints and private outputs on Vast; publish only allowlisted operational status.
6. Continue tuning only from measured bottlenecks. Report the measured 10,000-record epoch time, projected 100-epoch wall time, quality deltas, total spend, and remaining gap to 48 hours.

## Acceptance evidence

- Generated dataset: 10,000 unique train roots, 1,792 dev roots, 1,792 test roots, all certificates replayed, required split boundaries validated, and new SHA-256 pinned into the run manifest.
- Model contract: eight structural blocks, 136,421,807 parameters, and all 102 inputs selected and status-accounted for.
- Multi-GPU semantics: matching replica parameters, one logical batch schedule, averaged gradients applied once, and identical master/replica weights after each update.
- Runtime and quality: measured on the exact two RTX 3060 target; report full input/model/workload fingerprint and quality deltas separately from source/build checks.
- Operations: total project charges remain below $20 and the owned instance is verified stopped at the end.

- The run manifest now supports an absolute `target_attempts` cap. For a 10,000-record panel, batch size 4 and 100 epochs mean 250,000 updates total; the manifest requests all 250,000 in one invocation, and resume clamps to the remaining updates. The source check validates this behavior.

The builder preserves the original model, all 102 input slots, 14 all-to-all alphabets, the v25 missing-token schema, two devices, four sampled neighbors, and the 250,000-update target. It requires an explicit source-pinned feature-context profile and never synthesizes contexts from width. GitHub Actions run 48 passed: Python manifest tests, seven Rust manifest tests, CUDA binary build, and a synthetic manifest check selecting 102 model inputs. That synthetic check validates schema and provider registration only; it does not establish per-state feature coverage or model quality.

The n=10 test bundle must not be described as full multi-width coverage. Keep all 102 input slots and use the v25 missing-token contract for unavailable computations; do not fabricate contexts.
- The 48-hour target and holdout quality remain unverified. At 250,000 updates, the 48-hour ceiling requires an end-to-end average of at most 0.6912 s/update, including feature computation, data movement, and checkpointing. The earlier 38:15-per-10k measurement used a two-block network and is not a runtime estimate for the required eight-block model. Next acceptance requires an explicit, source-backed context profile and a budget-gated 2x3060 run that records epoch throughput and quality on the holdout while keeping results on Vast.

## Multi-GPU and measurement code audit (2026-11-20)

- The native CUDA trainer already supports two replicas in `native/src/nn_training/trainer/device/data_parallel.rs`. It draws one logical batch, weights each replica's loss and gradients by its share of the batch, reduces flattened gradients on the master, applies one AdamW update, and synchronizes replica parameters. The current manifest selects CUDA devices 0 and 1, batch size 4, and sequential one-record gradients. Source inspection does not prove useful overlap, throughput, memory fit, or quality on 2x RTX 3060.
- The repository has a real-update `cnot103-benchmark` binary and a `cnot103-coverage` audit binary. `CNOT103_STAGE_PROFILE=1` records synchronized stage timings; bounded candidate-chunk profiling aborts before gradient computation or an update. These are the right remote measurements once a valid run profile and budget window are available.
- The v25 model path sanitizes non-computed feature payloads to zero before projection and passes their status through the learned missing-status projection. The existing `cuda_missing_all` source test checks that missing payloads of NaN, zero, and a large value produce the same outputs. This source test and the actual per-width status distribution have not been run on the current 2x3060 training data.
- The $20 controller still reserves 51 active hours plus seven days of stopped-storage cost. Its latest outcome is `budget_gate_prior_spend`; no new instance or charge was created. The user has authorized rental within the $20 cap, but this authorization does not override that cap.
